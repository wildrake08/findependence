# Project Constitution

## Governing model

This project uses the Canonical Software-System Lifecycle Bootstrap Framework.

Development proceeds through governed, bidirectionally traceable refinement:

Idea
→ Subject
→ Telos
→ Purpose
→ Outcome
→ Capability
→ Function
→ Mechanism
→ Requirement
→ Implementation Element
→ Runtime realization

Material implementation must remain traceable upward to the Subject whose condition ultimately justifies the system.

Material accepted system responsibility must remain traceable downward to realization or have an explicit outstanding disposition.

## Foundational automation rule

Automation is broader than AI.

AI may propose, generate, analyze, or act only within explicit authority and execution boundaries.

Canonical operating pattern:

AI proposes/acts
→ deterministic automation validates
→ assurance evaluates
→ legitimate human authority gates where required.

AI capability does not imply AI authority.

## Gate rule

Passing a lower-level gate does not imply satisfaction of a higher-level gate.

Examples:

- code correctness does not establish Mechanism effectiveness;
- Mechanism realization does not establish Capability;
- Capability evidence does not establish Outcome attainment;
- Outcome evidence does not establish Telos attainment.

## Canonical-source precedence

1. Applicable legitimate external authority
2. Human-ratified Constitution and Governance
3. Canonical semantic artifacts
4. Canonical Requirements and accepted design decisions
5. Implementation policy
6. Generated artifacts

Lower-precedence artifacts may not silently override higher-precedence artifacts.

## Change

Canonical state is never rewritten without history.

Material change uses governed:

Change
→ impact analysis
→ authority evaluation
→ reassessment
→ enactment
→ ChangeEvent

Supersession and reopening preserve historical state.

## Framework reopening

The foundational framework is reopened only when concrete evidence demonstrates a materially necessary distinction that cannot be represented faithfully using the existing primitives, relationships, derived artifacts, governance, lifecycle, automation, or assurance model.
